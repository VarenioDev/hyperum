## 1. Scope проекта

### 1.1. Назначение системы

HyperUm — система гиперперсонализации образовательного процесса
на основе графа знаний и ML-моделей. Работает как **интеллектуальный
ассистент учителя и репетитора**: наставник задаёт тему, а система
подбирает **персональный набор заданий для каждого ученика** на основе
его графа знаний.

**Ключевое отличие** от существующих адаптивных систем (Учи.ру, ЯКласс):
система **не заменяет** учителя и **не раздаёт** всем одинаковые задания.
Она даёт учителю возможность за одно нажатие получить **N различных
тестов для N учеников**.

**Научная цель:** собрать данные пилота и обучить модель (graph-aware
Knowledge Tracing), которая заменит эвристический mastery и улучшит
подбор заданий. См. `research.md`.

### 1.2. Целевые пользователи

| Роль | Описание | Контекст |
|------|----------|----------|
| **Ученик** | Решает назначенные задания, следит за прогрессом | Школа, платформа |
| **Учитель (owner)** | Создаёт классы, генерирует тесты, анализирует | Школа |
| **Репетитор** | Точечная работа с 1–10 учениками | Платформа |
| **Гость** | Пробует демо-режим на лендинге | Публичный |
| **Администратор** | Управляет tenant'ом | Оба контекста (не в MVP) |

### 1.3. Контексты применения

| Контекст | Площадка | Статус |
|----------|----------|--------|
| **Школьный** | Лицей при ТПУ (3 класса, 67 учеников) | ✅ Апробация идёт |
| **Платформенный** | Онлайн-платформа ПолиУм | 🔴 Пилот намечен на февраль 2027 |
| **Демонстрационный** | Лендинг hyperum.polyum.ru | ✅ Работает |

Ядро системы **не зависит** от контекста. Различается только
организационная модель (`groups.kind` + роли).

### 1.4. Основные функции

1. ✅ Ведение банка заданий с разметкой по навыкам и сложности.
2. ✅ Автоматическая multi-skill разметка заданий через DeepSeek.
3. ✅ Приём ответов через Яндекс.Формы → CSV (fallback).
4. ✅ Приём ответов через PWA ученика.
5. ✅ Автоматическая проверка ответов с нормализацией.
6. ✅ Расчёт mastery по каждому навыку (взвешенный + сглаженный).
7. ✅ Генерация **персональных тестов** для каждого ученика.
8. ✅ Граф знаний ученика и класса (Neo4j + Cytoscape.js).
9. ✅ Дашборд ученика и учителя (PWA).
10. ✅ Demo-режим на лендинге (без регистрации).
11. ✅ Регистрация учеников по инвайт-коду.
12. ✅ Multi-tenancy (архитектурно).
13. 🔴 Рекомендации и прогнозы на ML-моделях (BKT / graph-BKT).
14. 🔴 A/B тест гиперперсонализации.
15. 🔴 Интеграция с ПолиУмом через REST API.

### 1.5. Границы ВКР

**Входит в разработку:**
- Ядро: БД, граф знаний, ML-модуль.
- Backend API (FastAPI).
- Приложение ученика и учителя (PWA).
- Демо-режим.
- Апробация в двух контекстах (школа + платформа).
- Научный эксперимент (BKT, graph-BKT, A/B).

**Не входит в разработку:**
- Платформа ПолиУм (используется как площадка).
- Нативные приложения iOS/Android.
- Интеграция с электронным журналом.
- Генерация заданий с нуля (используется банк).

## 7. Риски

| Риск | Вероятность | Влияние | Митигация |
|------|-------------|---------|-----------|
| Мало данных для ML | Средняя | Высокое | Сбор с сентября, ~3000–5000 ответов к марту |
| Не хватит времени на BKT | Средняя | Высокое | Приоритет: BKT > graph-BKT > A/B |
| A/B не получится организовать | Высокая | Среднее | Замена на «до/после» |
| Потеря данных | Низкая | Катастрофа | **Бэкапы (F56)** |
| Смена научрука / требований | Низкая | Среднее | Документация = быстрая адаптация |
| Один разработчик | Высокая | Высокое | Автоматизация, чёткие приоритеты |
