## 1. Scope проекта

### 1.1. Назначение системы

HyperUm — система гиперперсонализации образовательного процесса на основе
графов знаний и ML-моделей.

Система работает как **интеллектуальный ассистент учителя и репетитора**:
наставник задаёт тему и цель, а система подбирает **персональный набор
заданий для каждого ученика** на основе его графа знаний.

Ключевое отличие от существующих адаптивных систем: система **не заменяет**
учителя и **не раздаёт** всем одинаковые задания. Она даёт учителю
возможность за одно нажатие получить **N различных тестов для N учеников**.

### 1.2. Целевые пользователи

| Роль | Описание | Контекст |
|------|----------|----------|
| **Ученик** | Решает назначенные задания, отслеживает прогресс | Школа, платформа |
| **Учитель** | Генерирует тесты, анализирует результаты | Школа |
| **Репетитор** | Подбирает задания для разбора | Платформа |
| **Администратор** | Управляет tenant'ом | Оба контекста |

### 1.3. Контексты применения и апробации

| Контекст | Площадка | Статус |
|----------|----------|--------|
| **Школьный** | Лицей при ТПУ (3 класса, 67 учеников) | ✅ Апробация идёт |
| **Платформенный** | Онлайн-платформа ПолиУм | 🔴 Пилот намечен на февраль 2027 |

Ядро системы **не зависит** от контекста. Различается только организационная
модель (`groups` + роли).

### 1.4. Основные функции системы

1. ✅ Ведение банка заданий с разметкой по навыкам и сложности.
2. ✅ Автоматическая разметка заданий через GigaChat.
3. ✅ Приём ответов через Яндекс.Формы → CSV.
4. ✅ Автоматическая проверка ответов с нормализацией.
5. ✅ Расчёт mastery по каждому навыку.
6. ✅ Генерация **персональных тестов** для каждого ученика.
7. ✅ Дашборд учителя (Streamlit, 5 экранов + генератор).
8. 🟡 Приём ответов внутри приложения (PWA ученика).
9. 🔴 Рекомендации и прогнозы на ML-моделях.
10. 🔴 Синхронизация mastery в граф Neo4j.
11. 🔴 Интеграция с ПолиУмом через REST API.
12. ✅ Поддержка multi-tenancy (архитектурно).

### 1.5. Границы ВКР

**Входит в разработку:**
- Ядро: БД, граф знаний, ML-модуль.
- Backend API.
- Приложение ученика (PWA).
- Дашборд учителя и репетитора.
- Апробация в двух контекстах.

**Не входит в разработку:**
- Платформа ПолиУм (используется как площадка).
- Нативные приложения iOS/Android.
- Интеграция с электронным журналом.
- Генерация заданий с нуля.

## 4. Userflow: Ученик

Ученик — **получатель заданий**. Он решает то, что назначил учитель.

### 4.1. Получение теста от учителя (основной) — 🔴

1. Учитель сгенерировал тест и отправил классу.
2. Ученик видит badge в приложении.
3. Авторизуется → дашборд: активный тест + граф знаний.
4. Решает задания по порядку.
5. После каждого ответа — обратная связь.
6. Видит **анимацию обновления графа**.
7. Завершает → итог.

### 4.2. Одно задание от учителя — 🔴

1. Учитель отправил одно задание.
2. Ученик видит его на дашборде.
3. Решает → получает обратную связь.

### 4.3. Отслеживание прогресса — 🔴

1. Открывает дашборд.
2. Видит свой граф (зелёный/жёлтый/красный).
3. Тапает на узел → карточка навыка.
4. Видит историю и рекомендации.

### 4.4. Решение через Яндекс.Формы (fallback) — ✅

1. Учитель дал тест через Я.Формы.
2. Ученик решает там.
3. Учитель загружает CSV.
4. Mastery обновляется.

## 5. Userflow: Учитель

Учитель — **центральная фигура**. Генерирует тесты, анализирует.

### 5.1. Генерация теста для класса (основной) — ✅

1. Открывает дашборд → **«🎯 Создать тест»**.
2. Выбирает класс, тему, число заданий.
3. Нажимает **«✨ Сгенерировать»**.
4. Система смотрит граф каждого ученика → подбирает персональные наборы.
5. Превью: Иванов — 5 заданий, Петров — 5 заданий, Сидорова — 5 заданий.
6. Просматривает, при необходимости правит.
7. **«💾 Сохранить черновик»**.
8. Далее — экспорт в Я.Формы или отправка в PWA (в разработке).

**Пример:**

Тема «Циклы», 5 заданий, класс 10А (25 учеников):
- Иванов: 2 задания на `s_nested`, 3 на комбинацию `s_for` + `s_while`
- Петров: 3 на `s_while`, 2 на `s_nested`
- Сидорова: 4 на базовый `s_for`, 1 на `s_while`
- …

Один клик → 25 уникальных тестов.

### 5.2. Генерация для одного ученика — 🟡

1. Открывает профиль ученика.
2. Нажимает «Создать тест».
3. Указывает тему и число заданий.
4. Система подбирает по графу **этого** ученика.

### 5.3. Отправка одного задания — 🔴

1. Открывает класс или профиль.
2. Нажимает «Отправить задание».
3. Выбирает навык.
4. Система предлагает 3–5 заданий.
5. Отправляет.

### 5.4. Загрузка результатов из Я.Форм — ✅

1. Скачивает CSV.
2. Открывает дашборд → «Загрузить ответы».
3. Загружает.
4. Система пересчитывает mastery.

### 5.5. Анализ класса — ✅

1. Открывает дашборд.
2. Тепловая карта: ученики × навыки.
3. Топ проблемных тем.
4. Отстающие ученики.
5. Прогресс после теста.
6. Клик на ученика → граф знаний.
7. Решение: сгенерировать тест / отправить задание / разобрать.

### 5.6. Подготовка к контрольной — 🟡

1. Выбирает навыки к контрольной.
2. Система показывает, кто не готов.
3. Генерирует персональные тесты для неподготовленных.
4. Отправляет.
5. Через неделю — проверка прогресса.

## 6. Userflow: Репетитор

Репетитор — **точечная работа** с 1–10 учениками.

### 6.1. Отличия от учителя

| Аспект | Учитель | Репетитор |
|--------|---------|-----------|
| Учеников | 20–30 | 1–10 |
| Режим | «Пакетно»: тест классу | «Точечно»: задание для разбора |
| Модель данных | `group(kind='class')` | `group(kind='one_on_one')` |
| Цель | Освоение программы | Подготовка / закрытие пробелов |

### 6.2. Подбор задания для разбора (основной) — 🔴

1. Авторизуется на ПолиУме.
2. Открывает HyperUm как встроенный модуль.
3. Видит учеников с краткой сводкой.
4. Выбирает ученика.
5. Видит граф + рекомендации системы:
   - «Слабое место: вложенные циклы (mastery 0.32)»;
   - «Prerequisite в норме»;
   - «10 дней не практиковал».
6. Нажимает **«Подобрать задание для разбора»**.
7. Система предлагает 3–5 заданий с обоснованием.
8. Выбирает задание → ученик решает → граф обновляется.

### 6.3. Домашнее задание — 🔴

1. Выбирает ученика → «Сгенерировать ДЗ».
2. Указывает число заданий.
3. Система подбирает по графу.
4. Отправляет.

### 6.4. Анализ прогресса — 🔴

1. Открывает профиль.
2. Видит динамику, историю, прогноз.
3. Принимает решение о стратегии.

## 9. Связь с ВКР

**Главы:**
- Глава 1 — обзор (knowledge tracing, графы, рекомендательные системы).
- Глава 2 — проектирование (архитектура, модель данных, ML).
- Глава 3 — реализация (MVP, пилот, анализ).

**Гипотезы:**

- **H1.** Динамически калибрующийся граф знаний даёт более точную оценку mastery, чем статические модели.
- **H2.** Ансамбль ML-моделей подбирает задания точнее, чем единая модель или правила.
- **H3.** Система снижает временные затраты учителя на подготовку персональных заданий.
- **H4.** Гиперперсонализация повышает прирост освоения материала.
- **H5.** Система сохраняет эффективность при переносе школа → платформа без изменения ядра.
- **H6.** Использование клиентского приложения даёт более точную оценку за счёт детальных логов.
