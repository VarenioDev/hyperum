# Страница ученика и результаты тестов — F70/F71

Реализовано локально 2026-10-15. Не опубликовано. VPS и рабочие данные при разработке не использовались.

## Что изменилось

- Экран класса: вкладки «Ученики» и «Тесты», поиск по имени, последний назначенный тест с конкретным прогрессом. Приглашение свёрнуто, для пустого класса раскрыто. Заявки вынесены в отдельный блок. Кнопка «Создать тест» подходит обоим режимам генератора.
- `/teacher/assignment/:id`: результаты по последней попытке в каждой позиции, количество начавших/завершивших, выполненных/верных заданий. На компьютере — матрица, на телефоне — раскрываемые строки учеников. Ячейка открывает условие, ответ и историю попыток с пагинацией. Сохранённый черновик можно проверить и отправить.
- Персональные наборы явно отличаются от общего: один номер не означает одно и то же задание. Совпадение наборов определяется по ID и порядку заданий.
- `/teacher/student/:id`: обзор, интерактивный граф знаний и история тестов/ответов. Граф использует существующий `GraphView`, позволяет выбрать тему, показать навыки без данных и открыть ответы по навыку. Есть доступный с клавиатуры список навыков. «Подобрать тест» передаёт ученика и, при выборе навыка, его тему в генератор.
- Новые отчёты и граф проверяют владение классом/учеником. Автор теста видит его результаты; принадлежность одному tenant сама по себе не даёт доступ к ученикам другого учителя.

Расширенная аналитика класса, рейтинг сложности заданий и тепловая карта остаются в F67/F73. Восстановление исторической привязки ответов не выполняется.

## Попытки и миграция 019

`responses.assignment_id` хранит точный тест. `context` различает `assignment`, `practice`, `legacy`. Составной внешний ключ запрещает привязать ответ к заданию, которое не назначалось этому ученику в этом тесте. Сервер отклоняет чужие и неотправленные тесты до проверки ответа.

Последняя попытка определяется по `created_at DESC, id DESC` отдельно для `(assignment_id, student_id, task_id)`. Пропуск и «сдался» — самостоятельные состояния; они закрывают позицию, но не считаются верным ответом. Нерешённая позиция остаётся без ответа. Граф освоения навыков продолжает учитывать всю историю, а не только последние попытки.

Миграция **не удаляет и не перераспределяет старые ответы**. Они получают `legacy`, остаются в истории и освоении навыков. До этой версии нельзя было достоверно отличить решение в тесте от самостоятельной практики того же задания. Поэтому старые ответы не включаются в новую матрицу, а прежнее завершение обозначается как «Завершён до обновления». В тесте ученика также есть пояснение, если найдены возможные старые ответы.

В сводках «верно / всего» знаменатель включает все назначенные позиции, а выполнение показано отдельно: отсутствие ответа не выдаётся за ошибку. Это не школьная отметка и не сравнение учеников с разными наборами.

## Локальная проверка

```powershell
cd pwa
npm ci
npm run build
npm run test:reports
npm run test:generation
cd ..
.\.venv\Scripts\python.exe -m unittest discover -s tests -p 'test_*.py' -v
```

`test_teacher_reporting.py` проверяет сервисы и API на моках. `test_teacher_postgres.py` выполняет настоящие SQL-запросы приложения и миграции в PostgreSQL в памяти через dev-зависимость [PGlite](https://pglite.dev/docs/). Тестовый процесс не использует DSN приложения и не открывает рабочие базы. Neo4j-синхронизация в тестах подменена.

Проверяются повтор задания в двух тестах, отдельная практика, последняя неверная попытка после верной, одинаковые timestamps, пропуск/сдача, восстановление прогресса, ограничения миграции, история по навыку и доступ другого учителя.

`npm run test:reports` проверяет рендер страниц, ссылки, предвыбор генератора, Markdown/KaTeX и создаёт статические примеры с искусственными данными в `logs/teacher-report-preview/`. Это не браузерный тест жестов и взаимодействия с canvas: их нужно проверить вручную на компьютере и телефоне.

## Самостоятельный деплой

Сначала включить изменения в коммит, отправить в репозиторий и обновить рабочую копию VPS. Учитывать существующие незакоммиченные изменения, не сбрасывать их. Перед миграцией сделать актуальный бэкап привычным способом.

На VPS из `/root/hyperum`:

```bash
docker compose -f docker-compose.prod.yml build backend
docker compose -f docker-compose.prod.yml exec -T postgres sh -c 'psql -U "$POSTGRES_USER" -d "$POSTGRES_DB" -v ON_ERROR_STOP=1' < migrations/019_response_assignment.sql
docker compose -f docker-compose.prod.yml up -d --no-deps backend
curl --fail http://127.0.0.1:8000/health/db
```

Применять **только новую миграцию 019 и один раз**. Она выполняется транзакцией. `scripts/migrate.ps1` перебирает все старые миграции и для обновления существующей базы здесь не подходит. Новый backend требует 019; сначала миграция, затем перезапуск.

Frontend собрать на ноутбуке (`npm ci`, `npm run build` из `pwa`). На VPS Node.js/npm ранее отсутствовали. Из корня проекта в PowerShell:

```powershell
tar -czf logs/teacher-reports-frontend.tar.gz pwa/dist
scp logs/teacher-reports-frontend.tar.gz root@188.130.251.160:/root/teacher-reports-frontend.tar.gz
```

Затем на VPS из `/root/hyperum`:

```bash
release_dir=$(mktemp -d /root/hyperum-frontend.XXXXXX)
tar -xzf /root/teacher-reports-frontend.tar.gz -C "$release_dir"
bash scripts/deploy_task_text_frontend.sh "$release_dir"
```

Скрипт публикации фронтенда сохраняет старые hashed assets, выставляет публичной статике права каталогов `755`/файлов `644`, затем публикует HTML и service worker. Это предотвращает повторение случая, когда `assets` с правами `700` давал 404. Скрипт обновляет только frontend: шаги backend/миграции выше выполняются отдельно.

Проверить HTTP 200 для нового JS/CSS из `index.html`, закрыть старые вкладки/PWA и открыть сайт заново. Не очищать данные сайта без необходимости. Для отката кода и статики добавленные поля можно оставить; удалять миграцию и новые ответы не требуется.

## Приёмка на своих тестовых аккаунтах

1. Класс: поиск по имени, вкладка тестов, приглашение, подтверждение учеников, редактирование и удаление из класса.
2. Общий и персональный тесты: открыть ячейки до/после ответа, проверить пять состояний, последнюю попытку и историю, переход к ученику и возврат обратно.
3. Назначить одно задание в двух разных тестах. Ответ в одном и в самостоятельной практике не должен менять второй.
4. Ученик: открыть граф, сменить тему, показать неизвестные навыки, выбрать узел/навык из списка, раскрыть его ответы. Подобрать тест — в генераторе уже выбраны ученик и тема.
5. Проверить отсутствие данных и исторические ответы. У чужого учителя тот же URL должен возвращать 404, у ученика API отчётов — 403.
6. Телефон: раскрытие строки результата, диалог задания, горизонтальный скролл формул/таблиц и управление графом.
