## Как пользоваться

- **Спринт** — блок задач на ~1 неделю.
- **Оценка** — рабочие часы/дни одного разработчика.
- **Ссылки на FR** — где в `requirements.md` формализовано требование.
- **Порядок спринтов** — рекомендуемая последовательность, не жёсткий контракт.
- **Сверка:** 2026-10-13, по текущему рабочему дереву, включая незакоммиченные изменения. Для релиза Markdown/LaTeX также проверены сборка, production-БД, метки и публичное демо; остальные статусы не означают полного аудита production.
- **Обновление 2026-10-15:** F68, F69, F28 (без вложений), F76 реализованы и проверены локально на искусственных данных. Деплой, проверка с рабочими БД и визуальная приёмка ещё не выполнялись.
- **Статусы:** задачи без отдельной отметки в спринтах остаются в планах. Оценки частично выполненных задач относятся к оставшейся работе.
- **Закрытые задачи:** прежние статусы сохранены; наличие скрипта бэкапа не подтверждает настройку cron или успешное восстановление в production.

### F65. Очистка LaTeX-дублей при импорте

**Статус:** 🟡 Частично реализовано

**Приоритет:** SHOULD  
**Оценка остатка:** оценить интеграцию нормализации в регулярный импорт

**Проблема:** в исходниках заданий часто **дублируют** запись: `\( G(n) \) G(n)` — на случай, если LaTeX не отрендерится. В БД это выглядит как `G(n) G(n) G(n)` после отрисовки.

**Уже реализовано:** [`ml/normalize_task_text_v2.py`](../ml/normalize_task_text_v2.py) нормализует CSV через DeepSeek, сохраняет исходник и кандидатов, кэширует ответы. `ml.verify_task_texts` выполняет отдельную смысловую проверку; `ml.finalize_task_texts` требует закрыть все замечания перед созданием итогового CSV. Ручные согласования привязаны хэшами к исходнику и кандидату. Реальный банк VPS (976 заданий) проверен; 746 текстов обновлены транзакцией через `scripts.task_text_release`, разметка отсутствовавших 201 задания восстановлена. ID, ответы и связи сохранены; есть бэкапы БД, текстов и фронтенда. Детали — [`task-normalization.md`](task-normalization.md).

**Старый скрипт:** `ml/normalize_task_text.py` на `16taskege.csv` захватывает лишний текст и не идемпотентен (все 201 изменённое задание меняются при повторной обработке). Не применять его к этим заданиям в БД.

**Осталось:**

1. Закрепить процесс «нормализация → проверка → импорт verified.csv», чтобы повторный импорт исходного CSV не возвращал дубли. API-нормализацию держать явным отдельным шагом.
2. Добавить удобный просмотр/согласование предупреждений для новых партий заданий, используя существующие отчёты и финализатор.

**Риск:** модель может изменить смысл; для новых партий обязательны проверки и сверка замечаний, как при обработке текущего банка.

**Разметка текущего банка:** восстановлена; 0 заданий без primary-метки DeepSeek. Новые/содержательно изменённые задания размечать после нормализации отдельным запуском.

### F73. Обновление `task_stats`

**Приоритет:** SHOULD  
**Оценка:** 2 часа  
**Ссылка:** FR-1.12 (новое)

**Проблема:** таблица `task_stats` создана в миграции 002, но в текущем коде нет её обновления. Нужна для F67 (сложность по заданиям).

**Уже есть:** `GET /api/v1/responses/task/{task_id}` считает статистику одного задания напрямую из `responses` через `responses_service.task_stats`. Это не обновление таблицы `task_stats`; для F73 всё ещё нужны агрегат и расписание пересчёта.

**Что делать:**

1. Скрипт `ml/update_task_stats.py`:
   ```sql
   INSERT INTO task_stats (task_id, attempts_total, correct_total, avg_time_sec, updated_at)
   SELECT r.task_id, COUNT(*), SUM(CASE WHEN r.correct THEN 1 ELSE 0 END),
          AVG(r.time_sec), now()
   FROM responses r
   WHERE r.correct IS NOT NULL
   GROUP BY r.task_id
   ON CONFLICT (task_id) DO UPDATE SET
       attempts_total = EXCLUDED.attempts_total,
       correct_total = EXCLUDED.correct_total,
       avg_time_sec = EXCLUDED.avg_time_sec,
       updated_at = now();
   ```
2. Cron: `0 4 * * *` (после бэкапа в 3:00).

### F76. Перегенерация конкретного задания в превью

**Статус:** реализовано локально (2026-10-15), не развёрнуто; зависимость F28 включена в скоуп.

**Приоритет:** MUST  
**Оценка:** 1 день  
**Ссылка:** FR-5.18 (новое)

**Зачем:** генератор может выдать неоптимальное задание (дубль, слишком сложное). Учитель должен **заменить одно задание**, не переделывая весь тест.

**Реализовано:**

1. **Backend:** `POST /api/v1/assignments/regenerate-task`:
   ```json
   {
     "group_id": "uuid",
     "topic": "Название темы",
     "student_ids": ["uuid"],
     "personalize": true,
     "task_id": "uuid",
     "exclude_task_ids": ["uuid1", "uuid2"]
   }
   ```
   Возвращает `{task: GeneratedTask, match: "same_skill" | "neighboring_skill"}`. Навык, сложность и mastery сервер получает самостоятельно.

2. **Frontend:**
   - В карточке задания — «Заменить»; в общем тесте — «Заменить у всех».
   - В персональном режиме меняется позиция одного ученика; в общем — одна позиция у всех получателей.
   - Сначала сохраняется основной навык, затем рассматриваются соседние по графу навыки только внутри темы. Приоритет: расстояние по графу, близость сложности, существующий скоринг.
   - Исключаются задания текущего набора и уже отклонённые варианты в этом превью. Ошибка сохраняет исходный набор.
   - После сохранения набор фиксируется; изменение настроек до сохранения сбрасывает превью.

**Ограничение:** если альтернатив нет (мало заданий), вернуть 404 «Нет альтернатив».

**Уже реализовано:** `GET /api/v1/responses/assignment/{assignment_id}` возвращает число учеников, завершивших тест, число попыток и долю правильных ответов. Матрицы ответов и отдельного экрана результатов учителя пока нет.

**Осталось:**

1. **Список тестов** (`/teacher` → вкладка «Мои тесты»):
   - Название, класс, тема, дата, статус.
   - Прогресс: `X из Y учеников завершили`.
   - Средний % правильных.

2. **Детали теста** (`/teacher/assignment/:id`):
   - Метрики: сдали X/Y, средний %, среднее время.
   - Таблица «Ученик × Задание»: ✅/❌/⏭/— (не решал).
   - Клик на ячейку → ответ + правильный ответ.
   - Топ-3 «провальных» / «лёгких».

**Backend:**

- `GET /api/v1/assignments/{id}/matrix` — таблица.
- Расширить существующий `GET /api/v1/responses/assignment/{assignment_id}` или добавить новый endpoint прогресса с явным переходом клиентов. `GET /api/v1/assignments/{id}/progress` сейчас отсутствует.
