### F66. Единый pipeline для текста заданий

**Приоритет:** SHOULD  
**Оценка:** 0.5 дня  
**Ссылка:** NFR-4.10

**Зачем:** в заданиях будет markdown (таблицы F63), LaTeX (F61), возможно HTML. Нужен единый движок рендеринга.

**Решение:**
- `react-markdown` + `remark-math` + `rehype-katex` + `remark-gfm`.
- Markdown-таблицы — из коробки.
- LaTeX — через `remark-math`.
- Санитизация — `rehype-sanitize`.

**Пример:**
```tsx
<ReactMarkdown
  remarkPlugins={[remarkMath, remarkGfm]}
  rehypePlugins={[rehypeKatex]}
>
  {task.text}
</ReactMarkdown>
```

### F65. Очистка LaTeX-дублей при импорте

**Приоритет:** SHOULD  
**Оценка:** 0.5 дня

**Проблема:** в исходниках заданий часто **дублируют** запись: `\( G(n) \) G(n)` — на случай, если LaTeX не отрендерится. В БД это выглядит как `G(n) G(n) G(n)` после отрисовки.

**Что делать:**

1. Функция `clean_latex_duplicates(text)` в `scripts/import_tasks.py`.
2. Паттерн: `\( ... \)` + следующий за ним plain-текст **без обёртки** → оставить только LaTeX.
3. Опция `--clean-latex` (по умолчанию выключено).
4. **Скрипт-миграция** `scripts/clean_latex_duplicates.py` — проходит по всем `tasks`, чистит дубли, обновляет `text`.

**Риск:** алгоритм может удалить лишнее. Тестировать на выборке 20–30 заданий.

**После этого — переразметить проблемные задания** через DeepSeek (модель видит кашу → размечает неточно).

### F73. Обновление `task_stats`

**Приоритет:** SHOULD  
**Оценка:** 2 часа  
**Ссылка:** FR-1.12 (новое)

**Проблема:** таблица `task_stats` создана в миграции 002, но **никогда не обновляется**. Нужна для F67 (сложность по заданиям).

**Что делать:**

1. Скрипт `ml/update_task_stats.py`:
   ```sql
   INSERT INTO task_stats (task_id, attempts_total, correct_total, avg_time_sec, updated_at)
   SELECT r.task_id, COUNT(*), SUM(CASE WHEN r.correct THEN 1 ELSE 0 END),
          AVG(r.time_sec), now()
   FROM responses r
   WHERE r.correct IS NOT NULL
   GROUP BY r.task_id
   ON CONFLICT (task_id) DO UPDATE SET
       attempts_total = EXCLUDED.attempts_total,
       correct_total = EXCLUDED.correct_total,
       avg_time_sec = EXCLUDED.avg_time_sec,
       updated_at = now();
   ```
2. Cron: `0 4 * * *` (после бэкапа в 3:00).

### F67. Дашборд учителя: полная статистика класса

**Приоритет:** MUST  
**Оценка:** 3–4 дня  
**Ссылка:** FR-6.11–6.13, FR-6.15  
**Объединяет:** F15–F17 (старая нумерация)

**Проблема:** сейчас учитель видит только список учеников со статусом. Нет общей картины класса.

**Что должно быть:**

1. **KPI класса:**
   - Средний mastery.
   - Число активных тестов.
   - % решённых заданий за 7 дней.
   - Число «молчунов» (не заходили ≥5 дней).

2. **🔥 Тепловая карта: ученики × темы** (главная фича):
   - Строки — ученики.
   - Колонки — темы (top-N или все).
   - Ячейка — средний mastery ученика по теме, цвет 🟢🟡🔴.
   - Клик по ячейке → детали (ученик, тема, навыки, ответы).
   - Клик по строке → карточка ученика (F70).
   - Сортировка: ФИО / mastery / число проблемных тем.
   - **Выбор класса** (dropdown) — учитель может смотреть разные классы.

3. **Сложность по темам:**
   - Средний % правильных по классу для каждой темы.
   - Топ-3 «проблемные» / Топ-3 «освоенные».
   - Клик по теме → задания с % правильных.

4. **Сложность по заданиям:**
   - Задания с низким % правильных (`<30%`).
   - Задания с высоким % правильных (`>80%`).

5. **Неуспевающие ученики:**
   - mastery < 0.3 по 3+ навыкам.
   - Или средний mastery < 0.4.
   - Или не заходили >7 дней.
   - Сортировка по критичности.

**Backend:**

- `GET /api/v1/mastery/class/{id}/dashboard` — единый агрегат (KPI + heatmap + топики + задания + отстающие).
- Или отдельные эндпоинты, если один слишком тяжёлый.

**Frontend:**

- Новый экран `/teacher/class/:id/analytics` (или вкладка внутри `TeacherClass`).
- Компоненты: `Heatmap.tsx`, `TopicStats.tsx`, `TaskStats.tsx`, `StrugglingList.tsx`.

### F76. Перегенерация конкретного задания в превью

**Приоритет:** MUST  
**Оценка:** 1 день  
**Ссылка:** FR-5.18 (новое)

     "target_difficulty": 0.55,

   - Локальный стейт: старая `task_id` заменяется на новую.

**Ограничение:** если альтернатив нет (мало заданий), вернуть 404 «Нет альтернатив».

## Критические зависимости

- **F61 → F65:** сначала рендер, потом очистка (чтобы видеть, что чистим).
- **F65 → переразметка:** после очистки LaTeX — переразметить задания через DeepSeek.
- **F73 → F67:** без `task_stats` нет «сложности по заданиям».
- **F68 → F69:** мультивыбор первее, потому что «одинаковый для всех» — частный случай.
- **F76 → F28:** перегенерация логически встроена в расширенное превью.
- **F61, F65, F74 → ML-фаза:** без них данные грязные.
