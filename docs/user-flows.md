# HyperUm — Сценарии пользователей

**Версия:** 1.0
**Дата:** 2026-10
**Назначение:** описать все пользовательские сценарии системы. По ролям. С реальными экранами и API-вызовами.

**Связанные документы:**
- `architecture.md` — архитектура
- `api.md` — эндпоинты
- `requirements.md` — требования

---

## 0. Роли и контексты

| Роль | Где работает | Основная задача |
|------|--------------|-----------------|
| **Ученик** | PWA (`/dashboard`, `/assignment/:id`, `/graph`, `/history`) | Решать назначенные тесты, следить за прогрессом |
| **Учитель (owner)** | PWA (`/teacher`, `/teacher/class/:id`, `/teacher/class/:id/generate`) | Создавать классы, генерировать тесты, анализировать |
| **Репетитор** | PWA + ПолиУм (в планах) | Точечная работа с 1–10 учениками |
| **Гость** | Landing (`/`), DemoTest (`/demo/test`) | Попробовать систему без регистрации |
| **Анонимный соискатель** | Join (`/join`) | Зарегистрироваться по коду класса |

## 1. Гость — Landing и Demo

### 1.1. Цель

Показать ценность системы за 30 секунд, без регистрации.

### 1.2. Экран `Landing` (`/`)

**Что видит гость:**

- Логотип 🧠 + название «HyperUm».
- Заголовок: «Персональные задания — каждому ученику».
- Подзаголовок: «Одна кнопка — N персональных тестов».
- **Главный CTA:** textarea «Опиши, что знаешь и не знаешь» + кнопка «✨ Получить тест».
- Три фичи-карточки: «Граф знаний», «Персональный подбор», «Без prerequisite-провалов».
- Ссылка «Войти →» в шапке.

### 1.3. Флоу «Попробовать demo»

```
1. Гость заполняет textarea (мин. 20 символов)
   Пример: «Я хорошо знаю системы счисления, умею переводить
            из 10 в 2. Плохо разбираюсь в кодировании
            изображений и звука.»

2. Клик «✨ Получить тест»
   → POST /api/v1/demo/start {description}
   → Backend:
      - rate_limit по IP (5/час)
      - cleanup старых demo-гостей (>24 ч)
      - DeepSeek парсит описание:
        {topic: "Кодирование", skills_known: [...], skills_unknown: [...]}
      - создаётся гость (tenant='demo')
      - устанавливается mastery: 0.85 known, 0.15 unknown
      - генерируется 5 заданий через select_tasks_for_student

3. Клиент получает {session_id, topic, tasks, reasoning}
   → сохраняет в sessionStorage['demo_session']
   → navigate('/demo/test')

4. Гость решает 5 заданий:
   - POST /api/v1/demo/response {session_id, task_id, answer}
   - Backend обновляет mastery гостя
   - Мгновенная обратная связь (✅/❌ + правильный ответ)

5. После последнего ответа — «🎉 Показать мой граф»
   → переключение в режим `graph`
   → GET /api/v1/demo/graph/{session_id}
   → Cytoscape.js визуализация

6. В режиме графа — CTA:
   «Хочешь такой же для своего класса?»
   → «Войти как учитель» → /login
   → «Пройти заново» → / (Landing)
```

### 1.4. Ограничения

- **Rate limit:** 5 запусков в час по IP. При превышении — 429 + сообщение.
- **TTL:** гость и все его данные удаляются через 24 ч при следующем запуске.
- **Нет сохранения ответов** на клиенте — всё в sessionStorage, теряется при закрытии вкладки.
- **Минимум 20 символов** в описании (защита от спама).

### 1.5. Что видит гость

**Экран DemoTest (решение):**
- Точки-индикаторы прогресса сверху.
- Текст задания.
- Поле ввода + «Проверить».
- Обратная связь inline.
- После ответа — «Дальше →».

**Экран DemoTest (граф):**
- Легенда: 🟢 Освоено / 🟡 В процессе / 🔴 Слабо / ⚪ Не изучалось.
- Cytoscape-граф.
- Клик на узел → `SkillCard` (модалка с описанием навыка).
- CTA-блок внизу.

## 2. Ученик — регистрация по коду

### 2.1. Откуда берётся код

Учитель создаёт класс → получает инвайт-код `A7K9P2`. Передаёт ученикам.

### 2.2. Экран `Join` (`/join`)

**Что видит ученик:**

- Форма: Код класса, ФИО, Email, Пароль.
- При вводе кода ≥4 символов — автоподгрузка:
  `GET /api/v1/groups/by-code/{code}`
  → показывает «✅ Класс: 10А, Учитель: Смирнова А. П.»
- Если код не найден — «Код не найден».

### 2.3. Флоу

```
1. Ученик вводит код → проверка → видит название класса.

2. Заполняет ФИО, email, пароль (мин. 6 символов).

3. Клик «Зарегистрироваться»
   → POST /api/v1/groups/join {code, full_name, email, password}
   → Backend:
      - создаёт users (status='pending')
      - создаёт memberships (status='pending')

4. Экран успеха:
   «📬 Заявка отправлена. Учитель подтвердит её в ближайшее время.»

5. Кнопка «Перейти ко входу» → /login
```

### 2.4. Что дальше

Учитель видит pending-учеников в `TeacherClass`, подтверждает (approve) → ученик становится `active` → может логиниться.

**Если ученик заходит до approve:** `status='pending'` в `users`. Логин разрешён, но данные класса недоступны. **TODO:** проверить реальное поведение (сейчас в `auth.login` нет проверки `status`).

- Кнопка «Войти».

- `authStore.setUser(...)`,

  - `student` → `/dashboard`
  - `owner` / `admin` → `/teacher`

### 3.2. Экран `Dashboard` (`/dashboard`) — ученик

**Что видит:**

1. **Приветствие:** «Привет, Иван!» + текущая дата.
2. **Метрики (3 карточки):**
   - «средний» — средний mastery по всем навыкам (%).
   - «освоено» — число навыков с mastery ≥0.8.
   - «подтянуть» — число навыков с mastery <0.5.
3. **Активные задания** — список `AssignmentCard` со статусом ≠ completed.
4. **Пройденные** — секция ниже, с иконкой ✅.
5. **Стоит подтянуть** — топ-5 слабых навыков, ссылка «Граф →».

### 3.3. API-вызовы Dashboard

```
GET /api/v1/assignments/my   → активные и пройденные тесты
GET /api/v1/mastery/me        → mastery по всем навыкам
```

- `GET /api/v1/recommendations/next`.

## 4. Ученик — решение теста

### 4.1. Переход

Из `Dashboard` → клик на `AssignmentCard` → `/assignment/:id`.

### 4.2. Экран `Assignment` (`/assignment/:id`)

**Шапка:**
- «← Выйти» → `/dashboard`.
- «X из N» — прогресс.
- Точки-индикаторы: серые (не решены), зелёные (верно), красные (неверно), серые-тёмные (пропущено).

**Основная область:**
- «Задание X из N · task_XXX».
- Текст задания.
- Поле ввода ответа + подсказка «Без пробелов и единиц измерения».
- Кнопки: «←», «Сдаться», «Проверить».

**После ответа:**
- Результат inline (✅ Верно / ❌ Неверно / ⏭ Пропущено).
- Ваш ответ / Правильный ответ.
- «Уровень освоения навыка: X%».
- Кнопки: «← Назад», «Дальше →», «🎉 Завершить тест».

**Модалка «Сдаться»:**
- «🤔 Точно сдаться?»
- «Это задание будет засчитано как нерешённое, и вернуться к нему ты уже не сможешь.»
- «Нет, вернуться» / «Да, сдаться».

### 4.3. Флоу

```
1. Ученик открывает Assignment.
   → GET /api/v1/assignments/{id}/tasks
   → Backend возвращает задания + previous_response (если уже решал)
   → Восстановление прогресса: если есть нерешенные — открыть первый нерешенный
     если всё решено — открыть последний

2. Ученик вводит ответ.
   → POST /api/v1/responses {task_id, assignment_id, answer, time_sec}
   → Backend:
      - answers_equal(answer, expected)
      - INSERT responses
      - update_mastery для всех навыков задания
      - sync_mastery_to_neo4j (best-effort)
      - автозакрытие assignment, если всё покрыто
   → Ответ: {correct, expected, new_mastery}

3. Или «Сдаться».
   → POST /api/v1/responses {skipped: true, surrendered: true}
   → correct=NULL, skipped=TRUE, surrendered=TRUE
   → master не обновляется

4. После всех ответов (или сдачи) — «🎉 Завершить тест»
   → /dashboard
   → queryClient.invalidate(['mastery','me'], ['assignments','my'])
```

### 4.4. Особенности

- **Дубликат ответа** на то же задание — новое `INSERT` в `responses`. В UI отображается **последний** ответ (см. `get_assignment_tasks`, `ORDER BY created_at DESC LIMIT 1`).
- **Таймер** — на клиенте (`startTimeRef.current`). Сбрасывается при смене задания.
- **Автозакрытие assignment** — backend сам решает, когда всё покрыто. UI это не контролирует.

## 5. Ученик — граф знаний

### 5.1. Экран `Graph` (`/graph`)

**Что видит:**

1. Легенда: 4 статуса с количеством.
2. Тумблер «Показать неизученные темы» (по умолчанию скрыты).
3. Подсказка «Тапните на узел, чтобы увидеть детали».
4. Cytoscape-граф.
5. Клик на узел → `SkillCard` (модалка).

### 5.2. Флоу

```
GET /api/v1/graph/student/{user.id}
→ Backend:
   - Neo4j: полный граф (modules, topics, skills, prerequisites)
   - PostgreSQL: mastery ученика
   - Объединение: node + mastery + status
```

### 5.3. Цвета и статусы

| Статус | Условие | Цвет |
|--------|---------|------|
| mastered | mastery ≥ 0.8 | 🟢 зелёный |
| learning | 0.5 ≤ mastery < 0.8 | 🟡 жёлтый |
| weak | mastery < 0.5 | 🔴 красный |
| unknown | нет данных | ⚪ серый |

### 5.4. SkillCard

Модалка с описанием навыка: название, модуль, тема, mastery, attempts, correct.

## 8. Учитель — управление классом

### 8.1. Экран `TeacherClass` (`/teacher/class/:id`)

**Что видит:**

1. Заголовок: имя класса + ✏️ (переименовать).
2. Подзаголовок: «Информатика · 22 учеников · 2 ждут».
3. Главный CTA: «✨ Сгенерировать персональные тесты».
4. `InviteCodeBlock`.
5. Секция «Ждут подтверждения (2)» — `PendingStudentCard` с Approve/Reject.
6. Секция «Ученики (22)» — `StudentRow` со статусом.

### 8.2. Статусы ученика в списке

`StudentRowWithMenu` показывает:

| Условие | Иконка | Текст |
|---------|--------|-------|
| Есть активные тесты + не заходил ≥3 дней | 🎯 + ⏰ | «X тестов не завершено · Y дней не заходил» |
| Есть активные тесты | 🎯 | «X тестов не завершено» |
| Последний тест провален (0/5) | ⚠️ | «Последний тест провален» |
| Есть пройденные, средний балл | ✅ | «Есть пройденные тесты · Последний: 4/5» |
| Всё пройдено, отличный результат | ✅ | «Все тесты пройдены · Последний: 5/5» |
| Ничего не делал | ⏳ | «Ещё не решал» |

### 8.3. Меню действий (⋯)

- ✏️ «Редактировать ФИО» → модалка → `PATCH /api/v1/groups/student/{id}`.
- 🗑 «Убрать из класса» → confirm → `DELETE /api/v1/groups/{id}/members/{sid}`.

### 8.4. Переименование класса

✏️ рядом с именем → модалка → `PATCH /api/v1/groups/{id}` {name}.

**Ошибка 409** «Класс с таким названием уже существует» — показывается в модалке.

### 8.5. Approve/Reject

`PendingStudentCard`:
- Approve → `POST /api/v1/groups/{gid}/approve/{sid}`.
- Reject → `POST /api/v1/groups/{gid}/reject/{sid}`.

После approve ученик переходит в `active`.

## 9. Учитель — генерация персональных тестов

### 9.1. Экран `TeacherGenerate` (`/teacher/class/:id/generate`)

**Что видит:**

1. Заголовок «Сгенерировать тест», подзаголовок «Класс 10А · каждому ученику — свой набор».
2. Форма:
   - Select «Тема» (`GET /api/v1/tasks/topics`).
   - Input «Заданий на ученика» (1–15, по умолчанию 5).
   - Кнопка «✨ Сгенерировать».
3. **Во время генерации** — прогресс-бар с текстом:
   - <30%: «Подбираем задания по графу знаний...»
   - 30–60%: «Проверяем prerequisite...»
   - 60–90%: «Распределяем diversity...»
   - ≥90%: «Финальная сборка...»
4. **Превью** — список `<details>` по ученикам. Каждый разворачивается в список заданий (код + текст).
5. **Форма сохранения** — Input «Название теста» + «💾 Сохранить» + «↻ Заново».
6. **После сохранения** — блок «✓ Черновик сохранён» + «🚀 Отправить ученикам».

### 9.2. Флоу

```
1. Учитель выбирает тему + число заданий → «✨ Сгенерировать»
   → POST /api/v1/assignments/generate {group_id, topic, n_tasks}
   → Backend:
      - для каждого ученика (shuffle):
         - mastery из student_mastery
         - prerequisite из Neo4j
         - IRT-scoring + diversity
      - возвращает per-student наборы + usage_stats

2. Превью. Учитель смотрит глазами (пока не может править — см. FR-5.7).

3. «💾 Сохранить»
   → POST /api/v1/assignments/save {title, group_id, topic, students}
   → assignment_id (draft)

4. «🚀 Отправить ученикам»
   → POST /api/v1/assignments/{id}/send
   → status='sent', sent_at=now()

5. Ученики видят тест в /assignments/my.
```

### 9.3. Что НЕ реализовано

- **Ручная правка** сгенерированного теста (FR-5.7) — MUST, но пока нет.
- **Генерация для одного ученика** (FR-6.7) — есть в API, нет в UI.
- **Отправка одного задания** (FR-6.8).

### 9.4. Ошибки генерации

Возможные ответы 400:

| Ошибка | Причина |
|--------|---------|
| «Класс не найден» | Неверный `group_id` |
| «В классе 10А нет активных учеников» | Все pending/blocked |
| «По теме «X» нет навыков» | Темы нет в `skills` |
| «По теме «X» нет размеченных заданий» | Нет `task_labels` для темы |

## 10. Репетитор (в планах)

### 10.1. Отличия от учителя

| Аспект | Учитель | Репетитор |
|--------|---------|-----------|
| Учеников | 20–30 | 1–10 |
| Режим | Пакетно: тест классу | Точечно: задание для разбора |
| Группы | `kind='class'` | `kind='tutor_group'`, `one_on_one` |
| Основной сценарий | Генерация N тестов | «Что задать Ване на этой неделе?» |

### 10.2. Планируемые сценарии

- **Подбор задания для разбора.** Смотреть граф ученика + рекомендации системы → выбрать задание.
- **Домашнее задание.** Число заданий + генерация → отправка.
- **Анализ прогресса.** Динамика mastery, история.

**Статус:** API готов (`/assignments/generate` работает для любых groups), UI — нет.
