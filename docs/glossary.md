# HyperUm — Глоссарий

**Версия:** 1.0
**Дата:** 2026-10
**Назначение:** единый язык проекта. Все документы и код используют эти термины.

---

## Предметная область

**Навык (skill)** — атомарная единица знания: «цикл `for`», «прямое условие Фано», «маска подсети». Имеет стабильный ID (`s_for`, `s_fano_direct`), имя, модуль, тему, эталонную сложность. Источник истины — `taxonomy/informatics_10_11.yaml`, дублируется в PostgreSQL (`skills`) и Neo4j (узел `:Skill`).

**Тема (topic)** — группа навыков внутри модуля. Пример: «Циклы», «Кодирование информации». Хранится как строковое поле в `skills.topic` и как узел `:Topic` в Neo4j.

**Модуль (module)** — крупный раздел курса: «Системы счисления», «Основы логики», «Алгоритмы и структуры данных». Узел `:Module` в Neo4j.

**Таксономия** — вся иерархия Module → Topic → Skill. Один YAML-файл на предмет.

**Prerequisite** — предпосылка. Связь `(:Skill)-[:PREREQUISITE]->(:Skill)`. «Нельзя решать задачи на вложенные циклы, пока не освоен обычный `for`». Хранится **только** в Neo4j.

**Задание (task)** — конкретная задача с текстом, ответом, типом. Имеет код `task_XXX`. Хранится в `tasks`.

**Разметка (label)** — привязка задания к навыку с оценкой сложности и уверенности. Одно задание может иметь **несколько** разметок (multi-skill): одна primary + 0–2 secondary. Хранится в `task_labels`.

**Primary-навык** — навык, который задание проверяет **в первую очередь**. Ровно один на разметку.

**Secondary-навык** — сопутствующий навык, который тоже задействован. 0–2 на задание.

**Сложность (difficulty)** — число в диапазоне [0.0, 1.0]. 0 — тривиальное, 1 — олимпиадное. Оценивается LLM (DeepSeek) или задаётся вручную.

**Ответ (response)** — попытка ученика решить задание. Хранится в `responses` вместе с полями `correct`, `skipped`, `surrendered`, `time_sec`.

## Оценка знаний

**Mastery** — оценка освоения навыка учеником. Число в [0.0, 1.0]. Основная метрика системы.

**Взвешенный mastery** — учитывает, был ли навык primary или secondary в задании. Primary → вес 1.0, secondary → вес 0.7.

**Байесовское сглаживание** — при малом числе попыток значение mastery тянется к 0.5 (prior). Формула: `(weighted_correct + 0.5×3) / (weighted_attempts + 3)`.

**Провал prerequisite** — ситуация, когда у ученика mastery prerequisite-навыка < 0.5. Задания, требующие такой навык, блокируются при генерации.

**Зона ближайшего развития (ZPD)** — диапазон, где задание оптимально сложно: вероятность правильного ответа ≈ 0.7. Соответствует mastery ≈ difficulty.

**IRT-подобная функция полезности** — формула скоринга заданий для конкретного ученика. Пик полезности при p_correct ≈ 0.7, бонус слабым ученикам, штраф за повторное использование.

**Уверенность (confidence)** — оценка LLM своей разметки. 0.9+ — очевидно, 0.5 — сомневается.

**Пропуск (skip)** — ученик не дал ответ, но задание считается покрытым. Не влияет на mastery напрямую.

**Сдача (surrender)** — ученик нажал «Сдаться». Финальный отказ от задания, вернуться нельзя.

## Генерация тестов

**Assignment** — сгенерированный тест. Один assignment содержит **персональные** наборы заданий для **каждого** ученика группы. Статусы: `draft` → `sent` → `completed`.

**Assignment_student** — связка «ученик ↔ тест». Хранит статус прохождения конкретным учеником: `pending`, `in_progress`, `completed`.

**Assignment_task** — конкретное задание конкретному ученику с позицией в его наборе.

**Генерация** — процесс подбора персональных наборов. Запускается учителем по теме и числу заданий. Работает через `assignments_service.generate_for_group`.

**Diversity** — механизм, не позволяющий одному заданию попасть слишком многим ученикам. Реализован как штраф в scoring и счётчик `usage_counter`.

**Usage stats** — статистика генерации: сколько уникальных заданий использовано, максимальное число повторов.

**Автозакрытие** — assignment автоматически переходит в `completed`, когда все задания покрыты ответами (или пропусками) со времени `sent_at`.

## Multi-tenancy

**Tenant** — изолированный «арендатор»: школа, платформа, demo. Имеет `tenant_id` (`school_lyceum`, `demo`).

**Global** — уровень данных, общий для всех: таксономия. `tenant_id = 'global'` или без tenant вообще.

**Shared** — уровень данных, общий между tenant'ами, но с сохранением авторства: банк заданий, разметка.

**Isolated** — уровень данных, доступный только внутри tenant'а: пользователи, ответы, mastery, группы.

**RLS (Row-Level Security)** — механизм PostgreSQL, ограничивающий видимость строк по политике. В HyperUm — по `tenant_id = current_setting('app.current_tenant')`.

**tenant_session** — контекстный менеджер в `backend/db/postgres.py`, устанавливающий RLS-контекст через `SET LOCAL app.current_tenant`.

**FORCE RLS** — режим, при котором политика действует даже на владельца таблицы. Используется для `responses`, `student_mastery`.

## Роли и аутентификация

**owner** — учитель/репетитор. Создаёт классы, генерирует тесты.

**student** — ученик. Решает задания.

**admin** — администратор tenant'а. В MVP не используется.

**JWT** — токен аутентификации. Access живёт 1 час, refresh — 30 дней.

**httpOnly cookie** — способ передачи JWT в PWA: JavaScript не может прочитать токен, защита от XSS.

**Bearer-токен** — альтернативный способ, для API-интеграций (ПолиУм).

## Группы

**Group** — объединение учеников. Три вида (`kind`):
- `class` — школьный класс (20–30 учеников)
- `tutor_group` — группа репетитора (3–10)
- `one_on_one` — индивидуальные занятия

**Invite code** — 6-символьный код класса. Ученик вводит код → регистрируется → попадает в `pending`. Учитель подтверждает → `active`.

**Membership** — связь ученика с группой. Статусы: `pending`, `active`, `rejected`.

**Pending** — ученик подал заявку, ждёт подтверждения учителя.

## Demo-режим

**Demo tenant** — отдельный tenant `demo` для публичного демо на лендинге.

**Demo guest** — анонимный посетитель, создаётся как `student` в demo tenant. Хранится 24 часа.

**Rate limit** — ограничение на число demo-запусков (5 в час по IP). In-memory.

**Cleanup** — удаление demo-гостей старше 24 часов. Запускается при каждом новом `/demo/start`.

## Клиенты

**PWA ученика** — веб-приложение (React + Vite + Tailwind), устанавливается на домашний экран. Экраны: Landing, Login, Join, Dashboard, Assignment, Graph, History, DemoTest.

**PWA учителя** — веб-приложение в том же проекте. Экраны: TeacherDashboard, TeacherClass, TeacherGenerate. Заменил Streamlit-дашборд.

**Streamlit-дашборд** — **устарел**. Оставлен в репозитории `dashboard/` как исторический артефакт.

**Landing** — публичная главная страница. Содержит demo-виджет.

**Cytoscape.js** — библиотека визуализации графа. Используется в `GraphView.tsx`.

**TanStack Query** — библиотека для data fetching в PWA (кэш, invalidate, mutations).

**Zustand** — state management в PWA. Используется для `authStore`.

## Backend

**Сервис** — модуль в `backend/services/`, содержащий бизнес-логику. Роутер тонкий, сервис толстый.

**Роутер** — модуль в `backend/api/`. Принимает HTTP, валидирует через Pydantic, вызывает сервис.

**Репозиторий** — в HyperUm не выделен: SQL пишется прямо в сервисах через SQLAlchemy `text()`.

**Pydantic-схема** — модель валидации запроса/ответа API. Лежит в `backend/models/`.

**Lifespan** — управление жизненным циклом FastAPI: startup (ping БД) → shutdown (close pools).

## Разметка через LLM

**DeepSeek** — основная LLM для разметки задач. Модель `deepseek-chat`. Батчинг по 10 заданий, JSON-ответ, валидация Pydantic.

**GigaChat** — альтернативная LLM. Использовалась раньше, оставлена в `label_tasks_with_gigachat.py`.

**Батчинг** — обработка нескольких заданий за один запрос. Снижает стоимость и время разметки.

**Reasoning** — текстовое обоснование разметки от LLM. Хранится в `task_labels.reasoning`.

## Нормализация

**answers_equal** — единая функция сравнения ответов в `ingest/normalize.py`. Защищает от `21.0` vs `21`, `FF` vs `ff`, лишних пробелов.

**Нормализация сложностей** — выравнивание распределения difficulty после LLM-разметки. Скрипт `ml/normalize_difficulty.py`. LLM склонны кластеризовать сложности в узком диапазоне.
